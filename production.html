役割と持ち物 誰が何を持つか

SOLUNA は既存のPA・照明を置き換えない。卓から1本もらい、客席のスマホと Pi スピーカーを同じ時計に乗せる。だから役割は「新しい操作卓を増やす」ではなく「いつもの担当に1つ持ち場を足す」。

P

プロダクション / 主催

  • 管理トークン(SOLUNA_ADMIN)の保管と、誰に渡すかの判断
  • セットリスト・曲・映像・ライトの最終確定
  • ゾーン旗・入場QRの印刷(/flags)
  • 終演後の数字(/api/stats)をスポンサー/レポートへ
F

FOH / 音響

  • サーバのノートPC(またはPi)と会場LAN
  • 卓のaux/matrix 1本 → USB I/F → source.py
  • ALIGN で位相を追い込む(品質の要)
  • 本番は NEXT と MUTE、DEVICES の「鳴っている数」監視
L

照明 / 映像 / 制御

  • OSC で cue(/soluna/cue /go /light)
  • LTC / タイムコードで発火時刻を固定
  • Art-Net / sACN で灯体を同じ時計に
  • /screen のノートをHDMIで投影
C

ステージクルー

  • Pi 箱の配置・電源・DAC/スピーカー接続
  • 箱のWi-Fi「SOLUNA」で /setup(SSH不要)
  • ゾーン割当は FOH の NODES から(箱に保存される)
  • 「箱が点かない/鳴らない」の一次切り分け
持ち物数メモ
Pi 箱6–9 / 1ステージ客席15m格子。1台が自動で時計の親、残りはスピーカー
PoE スイッチ + LAN1式有線が最良(±1〜3ms)。箱同士のWi-Fiでも小規模なら可
FOH ノート1–2サーバ兼。予備は開演前に STATE を EXPORT しておく
USB オーディオI/F1入力1chで十分。Dante なら DVS / AVIO / AES67 モード
印刷物ゾーン数+入場/flags と /flags?gate=1 からA4。背景グラフィックON
電源箱ごと停電しても箱は勝手に復帰する(設定は箱に残る)

事前準備 前日まで

1

素材を入れる

  • 曲(mp3/aac)・映像(mp4)・音声(mp3)を /admin からアップ
  • 各曲の長さを測って保存(自動進行の基準)
  • 大きな会場は SOLUNA_ASSET_BASE にCDN/R2を指定し tools/r2-sync.sh で同期
2

セットリストを組む

  • 1ステップ = 曲 + 映像 + ライトの束
  • 各ステップに光の見た目(パターン・2色・BPM)
  • DJ 交代は /dj のトークン付きリンクを本人だけに渡す
3

箱を焼く

  • tools/pi-flash.sh で SD を焼く(設定不要)
  • FOH ノートを必ず親にするなら SERVER=ws://<ip>:8900 で固定
  • DAC は刺せば自動(USB > I2S > 内蔵)
4

ネットワークを決める

  • 箱は有線PoE、観客は LTE + クラウド or 会場Wi-Fi
  • 箱の自前APは約20–30台まで=スタッフ・DJ用
  • Dante/AES67 を使うなら IGMP が通る VLAN の空きポートを1本
5

印刷

  • ゾーン旗 /flags、入場QR /flags?gate=1
  • 旗は客席に置く位置とゾーン名を一致させる
  • 入場QRは列の早い位置に(並んでいる間に音源を先読み)
6

リハーサル

  • 会場で ALIGN・ウォークテストを1回(実機の初回は必須)
  • 回線が不安なら docs/field-test.md の3キャリアテスト
  • 予備Macへ STATE を EXPORT しておく

設営 開場3時間前まで

1

箱を置く

客席に15m格子で6–9台。ステージから遠い列ほど後ろへ。電源を入れ、約1分待つ。1台が自動で時計の親になり、残りはスピーカーになる。

2

サーバを立てる

FOH ノートでサーバを起動し /admin を開く。Pi が親になる運用なら、どの箱の .local:8900/admin でも同じ画面。

# FOH laptop (LAN production)
SOLUNA_ADMIN=<secret> PORT=8900 python3 server.py
# optional bridges (LAN only, off by default)
SOLUNA_OSC_PORT=9000 SOLUNA_ARTNET=192.168.1.255:0 python3 server.py
3

ゾーンを割り当てる

/admin → NODES で各箱にゾーン(A=ステージ前 … F=最後方)、L/C/R、ゲインを ASSIGN。設定は箱に保存され、再接続でも再送される。

4

距離を入れる

ZONES に各ゾーンのステージ距離(m)を実測で入力。遅延は「距離÷343 + 15ms」で自動。またはステージ前で「現在地をステージに設定」→ 来場者はGPSで自動。

サウンドチェック 開場90分前

1

音を入れる

卓の aux/matrix を1本、USB I/F 経由で source.py へ。融合は --lead 0.08(約80ms)。Dante は DVS/AVIO か AES67 モード。

python3 source.py --input "Scarlett 2i2" --lead 0.08 --server ws://127.0.0.1:8900
# AES67 / Dante(AES67 mode)
python3 source.py --sap
python3 source.py --aes67 auto --lead 0.08
2

位相を合わせる(要)

クリック/リムショットを会場PAとグリッドの両方から出し、フラム(二重打ち)が消えるまで ALIGN を ±5 → ±1ms で追い込む。ここが音の品質を決める。全端末に即時反映。

3

歩いて確かめる

ZONES の 🔊 でゾーン単体を鳴らし、歩いて確認。遠いゾーンが小さいなら gain(dB) で持ち上げる。機種差は来場者側の ±12dB スライダー。

4

先読みする

開演30分前までに PRELOAD。DEVICES の preloaded が来場者数に近づくのを見る。FIRE 時のダウンロード集中をゼロにする。

判断の目安: 同期は LAN ±1〜3ms / LTE ±10〜20ms / Pi箱内 ±0.5ms。スマホは演出・光・映像まで。主音響は有線の Pi ノードが担う。

開場・本番 ドアオープンから終演まで

1

入場

入場QRを列の早い位置に。並んでいる間に音源が届き、中では通信なしで鳴る。観客は旗の近くでQRを読むだけ。

2

進行は NEXT だけ

SHOW パネルで NEXT を押すと全端末・全Piが同時に次のステップへ。AUTO をONにすれば曲が終わると自動で進む。単発は FIRE / LIGHT で割り込み。

3

止めるのは1操作

MUTE がキルスイッチ。全端末が即無音になり、解除で元のゲインへ戻る(位相は保たれる)。ハードカットは STOP。

4

見る数字を決める

DEVICES で playing(実際に鳴っている台数)/ failed / ctx suspended(ロック・サイレントで無音の可能性)/ battery<20%。接続数ではなく「鳴っている数」を見る。

iOS の注意: Web版は画面ロックで音が止まる。観客には「画面はつけたまま」を案内し、放置時は自動暗転(45秒)で節電する。止まった端末は ctx suspended に出る。

終演後 片付けと記録

1

数字を残す

/api/stats でピーク端末数・ゾーン別ピーク・発火したcue数・稼働時間。スポンサーやレポートにそのまま使える実測値。

2

状態を控える

STATE を EXPORT。次回同じ構成で始められる。別会場へ移すときは IMPORT で再配信。

3

片付ける

箱の電源を落とすだけ。設定はSDに残る。DAC・スピーカー・LANケーブルを箱ごとにまとめて戻す。

正直な制約 できないこと・未検証のこと

本番で期待値を外さないために、できないことを先に共有する。

!

音質は箱とスピーカー次第

15m格子の小型SPは「どこでも明瞭」。20kWのサブウォールではない。低音の量が必要なら既存PAと併用する。

!

iOS はロックで止まる

Web版は画面ロックで音が止まる(ネイティブ版は継続)。観客には画面オンを案内。

!

LTE は主音響に粗い

±10〜20ms。主音響は有線の Pi ノード、スマホは演出・光・映像に使う。

!

実機の初回は未検証の領域がある

Dante/LTC/照明卓/灯体は合成信号で検証済みだが実機接続は初回。屋外GPS精度・実iPhone多台数も未実施。初回は余裕のある lead で。

規模の目安: Pi 4 1台で 5,000 接続・CUE到達100%(開始ばらつき3.3秒 → その規模では lead ≥5秒)。2,000台なら0.9秒。LAN単一プロセスでは 10,000台を17秒で接続し、ばらつき791ms/猶予8秒。上限はサーバではなく無線。
